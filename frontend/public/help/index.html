Start here

Before you do anything

Confirm the yellow Sandbox banner. Stop immediately if the application does not say “REVOLUT SANDBOX · NO LIVE DATA.”
  1. 1
    Open the private application address supplied by your administrator.
  2. 2
    Sign in with your own account. Never use another person’s account.
  3. 3
    Enter the current six-digit authenticator code when requested. A recovery code is for emergency one-time use only.
  4. 4
    Check the Operations card. Continue only when it says Clear.
  5. 5
    Check the Backup card. If it says Missing, Stale, or Unavailable, do not authorize execution.

Expected result: You are signed in, the environment is Sandbox, Operations is Clear, and the backup is Fresh.

Routine procedure

Complete the daily check

  1. Read the yellow environment banner.
  2. Confirm Operations: Clear.
  3. Confirm Backup: Fresh.
  4. Look for cases marked Quarantined, Intake Hold, Information Required, Partial, or Blocked.
  5. Record the date, time, your name, and whether the check passed.
Stop condition: Operations is Blocked, backup is not Fresh, the Sandbox banner is missing, or a case has an unexplained Partial or Blocked execution.

Nine-step workflow

Work a funding case in order

An uploaded package creates a case. It does not prove money arrived and it does not authorize a payment.

  1. 1
    Upload package. Choose the private ZIP and select Upload to quarantine once.
  2. 2
    Review package health. Wait for scanning and validation to finish.
  3. 3
    Compare claims. Read what the sender claimed and what the checks found.
  4. 4
    Add cited evidence. Correct a claim only with a reason and evidence reference.
  5. 5
    Match the incoming credit. Use provider observations, never the uploaded package.
  6. 6
    Approve, reject, or request information. Approval is allowed only when every required check passes.
  7. 7
    Review payouts and fees. The total must exactly equal the matched receipt.
  8. 8
    Authorize and execute. Verify the exact plan, then re-enter password, fresh MFA, and phrase.
  9. 9
    Reconcile and export. Confirm final provider results and download the evidence record.

Review

Resolve findings without overwriting history

  1. Read each blocked reason and its “what is needed next” instruction.
  2. Obtain new evidence from an approved source.
  3. Add an amendment with the corrected value, reason, source, and evidence reference.
  4. Check that the machine review ran again.
  5. Do not mark a hard block as “accepted risk.” Hard blocks must be resolved by evidence or the case must be rejected.
Remember: The original claim stays in the record. Your amendment is added after it so reviewers can see what changed.

Independent evidence

Match the incoming funds

  1. Confirm all non-funding hard blocks are resolved.
  2. Select the funding refresh action.
  3. For a test only, use the clearly labeled Sandbox simulation option. Never describe it as real settlement.
  4. Confirm there is exactly one credit matching account, currency, amount, and reference.
  5. Continue only when Funding says Matched.
Do not continue when Funding says Possible Match, Unmatched, Awaiting Funds, or Reversed.

Human decision

Approve, reject, or request information

  • Approve: every required risk area passes, funding is Matched, and the purpose is understood.
  • Request information: evidence is missing or unclear but may be supplied safely.
  • Reject: the case is unacceptable, evidence cannot resolve it, or the package is unsafe.

Always write a short factual reason. Do not use “looks fine” or “approved by system.” The operator owns the human decision.

Money check

Review the exact funding plan

Check every line, including small fees.

  1. Confirm the receipt amount and currency match the observed credit.
  2. Confirm each beneficiary name and payment destination.
  3. Confirm each customer payout.
  4. Confirm the broker fee and provider fees.
  5. Confirm any reserve or refund is explicit.
  6. Add every line. The total must equal the receipt exactly.
Matched receipt = customer payouts + broker fee + provider fees + reserve/refund

High-impact action

Authorize and execute

  1. Read the plan version and digest shown by the application.
  2. Confirm no evidence, beneficiary, allocation, funding, or provider detail changed.
  3. Type the exact authorization phrase shown.
  4. Enter your password and a fresh authenticator code.
  5. Authorize once.
  6. Review the plan again before execution.
  7. Enter the separate execution phrase, password, and fresh code.
  8. Select Execute once and wait for the result.
Never click again because the screen is slow. A pending or unclear result must be reconciled before any further action.

Close the case

Reconcile and export evidence

  1. Select Reconcile for non-final provider results.
  2. Confirm every submitted payout is Completed.
  3. Confirm no later payout was submitted after a failed, pending, reverted, declined, or unclear result.
  4. Continue reconciliation until the case says Reconciled, or stop and escalate.
  5. Download the signed evidence bundle.
  6. Record the case reference, date, final state, and evidence filename.

Expected result: Case is Closed, Execution is Reconciled, and the signed evidence file is retained.

Stop safely

If something goes wrong

  1. Do not retry an authorization, execution, or submitted transfer.
  2. Write down the time, case reference, screen title, status, and the plain-language error.
  3. Do not include passwords, MFA codes, recovery codes, cookies, tokens, full account identifiers, balances, or package contents.
  4. Leave the case unchanged.
  5. Contact the named administrator through the approved support channel.

Always applies

Safety rules

  • Use Sandbox identities and low-value test amounts only.
  • Never use investor banking credentials.
  • Never treat an uploaded package as proof that funds arrived.
  • Never create a counterparty from uploaded instructions.
  • Never share passwords, MFA or recovery codes, tokens, cookies, or secret files.
  • Never change a case to make a warning disappear.
  • Never retry a payment with an unclear outcome.
  • Never use this application for live money.

Plain language

Glossary

Case
The complete review record for one funding request.
Claim
Something the sender says is true. A claim is not proof.
Evidence
A cited record used to support or correct a claim.
Finding
A problem, warning, or passed check produced during review.
Amendment
A dated correction that leaves the original claim visible.
Provider observation
Transaction information independently read from Revolut Sandbox.
Funding plan
The exact list of payouts, fees, reserve, and refund tied to one matched receipt.
Digest
A short fingerprint used to prove the plan did not change.
Reconcile
Ask the provider for the latest result and compare it with the case record.
Sandbox
A test environment. Its funds and identities are not real.

No matching guide section

Try a shorter word such as “funds,” “pending,” “upload,” or “backup.”
