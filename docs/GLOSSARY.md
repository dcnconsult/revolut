# Broker glossary and status guide

**Who this is for:** anyone reviewing or supporting a Sandbox case.

The workspace may use a technical label on screen. This guide explains what it
means in everyday broker language and what to do next.

## Useful words

| Workspace word | What it means in broker terms |
| --- | --- |
| Case | The protected work record for one request. |
| Client case ZIP | The single ZIP file received for the case. It contains submitted information; it is not proof or payment instructions. |
| Submitted case details | What the sender says is true. The workspace may call these “claims.” |
| Safe file list | The names, types, sizes, and safety results for files in a clean ZIP. The workspace may call this an “artifact inventory.” |
| New or unrecognised ZIP | A file that is safe to review but whose layout the workspace does not yet understand. It can still be useful for broker review. |
| Broker review | Your documented professional assessment of the submitted details and supporting records. |
| Finding | A passed check, question, warning, or stop reason shown by the workspace. |
| Needed next | The plain-language action required before the case can move forward. |
| Supporting record | Something you checked independently to support or correct a case detail. The workspace may call it “evidence.” |
| Recorded correction | A dated correction that keeps the original statement visible. The workspace may call it an “amendment.” |
| Sandbox test receipt | One test credit read from Revolut Sandbox that matches the expected account, currency, amount, and reference. |
| Matching | Exactly one Sandbox test receipt agrees with the expected details. |
| Payment plan | The exact list of test payouts, fees, reserve, and refund that uses the matching Sandbox test receipt. |
| Direct Transfer Test limit | The small limit used only for the technical account-connection check. It is not the limit for a broker case. |
| Sandbox case limit | The separate limit for a broker-confirmed Sandbox case. The case uses the full confirmed test amount within this limit. |
| Reconcile | Refresh the case from Revolut Sandbox and confirm the final result of the existing test. It does not start another payment. |
| Signed case record | The downloadable case history, including the original ZIP, review, decisions, Sandbox results, and proof that the record has not been changed unnoticed. |
| Quarantine | The protected holding area used while the ZIP safety check runs. |
| Sandbox | Revolut's test environment. Its test money and identities are not live. |

## Common case statuses

| Status on screen | Plain meaning | What you should do |
| --- | --- | --- |
| Quarantined | The ZIP has not passed the private safety check. | Wait. Do not open files or work around the check. |
| Intake Hold | The ZIP may be safe, but details are missing, inconsistent, or the layout is not yet recognised. | Read the safe file list and **Needed next** instruction. |
| Awaiting Broker | The case is ready for your broker review. | Review submitted details, findings, and supporting records. |
| Information Required | The case needs a specific answer or supporting record. | Request the named information and record where you checked it. |
| Approved | The broker decision passed the current checks. | Read the exact payment plan before authorising it. |
| Awaiting Funds | No matching Sandbox test receipt has been seen. | Refresh only when the workspace permits it. |
| Possible Match | More than one Sandbox test receipt may fit. | Stop and investigate; do not choose one by guesswork. |
| Matched | Exactly one Sandbox test receipt matches. | Continue only if all other checks also pass. |
| Reversed | A receipt that matched earlier no longer qualifies. | Stop. The earlier authorisation is no longer valid. |
| Awaiting Authorization | A payment plan exists but is not yet approved for the Sandbox test. | Read every plan line. |
| Authorized | The current plan may be run after the final confirmation. | Recheck the plan, then execute once. |
| Pending or unclear | Sandbox has not given a final answer, or the answer cannot be confirmed. | Use **Reconcile**; do not submit again. |
| Partial | Some test payouts completed and later ones did not. | Stop, reconcile the existing requests, and ask for support. |
| Blocked | The workspace cannot safely continue. | Stop and contact the administrator. |
| Reconciled | Every submitted test payout has a final confirmed result. | Download the signed case record and close the case. |
| Failed | The test did not complete safely. | Stop, keep the result, and ask for guidance. |
